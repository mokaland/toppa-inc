## 1. プロダクト概要

**ツミキリ**は、中小企業の経営者が「事務作業の山」から解放されるためのAIアシスタント。自然言語で指示するだけで、日常の事務作業をAIが代行するWebアプリケーション。MVPでは以下の3機能を優先して提供し、経営者の初期の「詰み」を解消することを目指す。

## 2. ターゲットユーザー

### ペルソナ: 田中 誠一（52歳）
- **職業**: 建設業の社長（従業員12名）
- **課題**: 現場監督しながら見積書・請求書・日報管理。事務員は1人だが追いつかない。
- **ITリテラシー**: LINEとExcelは使える。専門ツールは苦手。
- **予算**: 月3,000円以内なら即決。1万円超えると妻（経理担当）に相談。
- **口癖**: 「事務仕事さえなければ、もっと現場に出られるのに」

### ペルソナ: 佐藤 美咲（38歳）
- **職業**: 美容サロンオーナー（スタッフ5名）
- **課題**: 予約管理・顧客フォロー・SNS投稿・経理を一人でこなしている。
- **ITリテラシー**: InstagramとCanvaは使いこなす。Excelは苦手。
- **予算**: 効果が見えれば月5,000円OK。
- **口癖**: 「やりたいことはあるのに、手が足りない」

## 3. MVP機能詳細

MVPでは以下の3機能を最優先で提供する。Founding Engineerの実装計画と連携し、特にチャットアシスタントは先行して詳細化を進める。

### 3-1. 機能1: チャットアシスタント

経営者が自然言語で質問や指示を投げかけ、AIが即座に回答やアシストを行う機能。経営者の「ちょっとした相談」や「情報整理」の詰みを解消する。

#### ユーザーストーリー

1.  **認証済みユーザーとして、AIチャットに質問を投げかけたい。** (Founding Engineerにより認証機能の実装が完了しているため、この前提でチャット機能を利用できる)
2.  **AIチャットの応答が3秒以内に返ってきてほしい。** (迅速な意思決定を支援するため)
3.  **過去のチャット履歴を参照したい。** (会話のコンテキストを保持し、情報を追跡しやすくするため)
4.  **AIチャットが経営者の質問に特化した回答をしてほしい。** (一般的なAIではなく、事業課題解決に役立つ情報を得るため)
5.  **スマホからでもチャットを利用したい。** (移動中や現場でも手軽に相談できるようにするため)
6.  **重要なチャット内容は後から見返せるように保存したい。** (議事録やアイデアメモとして活用するため)

#### 画面遷移

```
ログイン → ダッシュボード
              └── チャット（トップ画面）
                    ├── 過去のチャット履歴一覧（左サイドバー）
                    └── チャット入力・表示エリア
                          ├── 入力フォーム（テキスト入力、音声入力アイコン）
                          ├── 送信ボタン
                          └── AI応答表示（リアルタイムストリーミング）
```

#### データモデル（`chat_messages`テーブル）

Founding EngineerのDBスキーマ定義を参考に、PdM視点での要件を記述。

| 項目名 | データ型 | 制約 | 説明 |
|--------|----------|------|------|
| id | UUID | PRIMARY KEY | メッセージの一意なID |
| user_id | UUID | NOT NULL, REFERENCES auth.users(id) | メッセージを送信したユーザーID |
| role | VARCHAR(10) | NOT NULL, CHECK ('user', 'assistant', 'system') | メッセージの送信元（ユーザー、AI、システム） |
| content | TEXT | NOT NULL | メッセージ本文 |
| created_at | TIMESTAMPTZ | DEFAULT NOW() | メッセージ作成日時 |

#### APIエンドポイント（チャット関連）

Founding EngineerのAPI設計を参考に、PdM視点でのリクエスト・レスポンスの要件を記述。

| エンドポイント | Method | 機能 | リクエストボディ例 | レスポンスボディ例 |
|---------------|--------|------|--------------------|--------------------|
| `/api/chat` | POST | チャット送信・AI応答取得 | `{"message": "今月の売上を上げるには？", "history": [...]}` | `{"response": "いくつか提案があります...", "message_id": "..."}` |
| `/api/chat/history` | GET | 会話履歴取得 | (なし) | `[{"id": "...", "role": "user", "content": "..."}, ...]` |
| `/api/chat/history/:sessionId` | GET | 特定セッションの履歴取得 | (なし) | `[{"id": "...", "role": "user", "content": "..."}, ...]` |

#### 非機能要件（チャット）

-   **レスポンス速度**: ユーザーのメッセージ送信からAIの最初の応答まで3秒以内。
-   **可用性**: 99.5%以上。
-   **セキュリティ**: 会話履歴はユーザーごとに分離し、RLS (Row Level Security) を適用。データは暗号化して保存。

### 3-2. 機能2: AIレポート生成

CSVまたはExcelファイルをアップロードし、自然言語で指示することで、AIがデータを分析し、日本語のレポートを生成する機能。経営者の「データ集計・分析」の詰みを解消する。

#### ユーザーストーリー

1.  経営者として、CSVファイルをアップロードして「先月の売上を部門別にまとめて」と指示したい。 (事務員に頼む手間を省くため)
2.  経営者として、AIが生成したレポートをPDFまたはMarkdown形式でダウンロードしたい。 (社内資料や報告書に活用するため)
3.  経営者として、レポート生成の進捗状況を確認したい。 (完了までの目安を知るため)
4.  経営者として、生成されたレポートの内容が正確であることを確認したい。 (意思決定の信頼性を確保するため)

#### 画面遷移

```
ダッシュボード → レポート生成
                    ├── ファイルアップロードエリア（ドラッグ＆ドロップ対応）
                    ├── 指示入力フォーム（自然言語）
                    ├── 「レポート生成」ボタン
                    └── レポート表示エリア（生成中ステータス表示、完了後にレポート内容表示）
                          ├── ダウンロードボタン (PDF/Markdown)
```

#### データモデル（`reports`テーブル）

| 項目名 | データ型 | 制約 | 説明 |
|--------|----------|------|------|
| id | UUID | PRIMARY KEY | レポートの一意なID |
| user_id | UUID | NOT NULL, REFERENCES auth.users(id) | レポートを生成したユーザーID |
| title | VARCHAR(255) | NOT NULL | レポートタイトル |
| file_name | VARCHAR(255) | NULLABLE | アップロードされたファイル名 |
| file_url | TEXT | NULLABLE | Supabase Storage上のファイルURL |
| prompt | TEXT | NOT NULL | ユーザーの指示内容 |
| result | TEXT | NULLABLE | AIが生成したレポート内容（Markdown形式） |
| status | VARCHAR(50) | NOT NULL, DEFAULT 'pending' | レポート生成ステータス ('pending', 'processing', 'completed', 'failed') |
| created_at | TIMESTAMPTZ | DEFAULT NOW() | レポート作成日時 |
| updated_at | TIMESTAMPTZ | DEFAULT NOW() | レポート更新日時 |

#### APIエンドポイント（レポート関連）

| エンドポイント | Method | 機能 | リクエストボディ例 | レスポンスボディ例 |
|---------------|--------|------|--------------------|--------------------|
| `/api/report/upload` | POST | ファイルアップロード | `multipart/form-data` | `{"file_url": "...", "file_name": "..."}` |
| `/api/report/generate` | POST | レポート生成指示 | `{"file_url": "...", "prompt": "先月の売上をまとめて"}` | `{"report_id": "...", "status": "pending"}` |
| `/api/report/:id` | GET | 特定レポート取得 | (なし) | `{"id": "...", "title": "...", "result": "..."}` |
| `/api/report/:id/download` | GET | レポートダウンロード | (なし) | (PDF/Markdownファイル) |

#### 非機能要件（レポート）

-   **処理時間**: ファイルサイズによるが、一般的なデータ量であれば30秒以内にレポート生成を完了。
-   **ファイル対応**: CSV, XLSX形式をサポート。
-   **データ保持**: アップロードされたファイルは一定期間後に自動削除。

### 3-3. 機能3: テンプレート書類生成

見積書、請求書、お礼状などのテンプレートを用意し、AIが自然言語の指示に基づいて情報を流し込み、書類を自動生成する機能。経営者の「書類作成」の詰みを解消する。

#### ユーザーストーリー

1.  経営者として、「○○建設さんへ、屋根修理の見積書を作って。金額は35万円」と指示したい。(書類作成に30分かかるのを3分にするため)
2.  経営者として、AIが作った書類をプレビューしてから確定したい。 (間違いがあると信用問題だから)
3.  経営者として、生成された書類をPDF形式で出力したい。 (取引先への送付や社内保管のため)
4.  経営者として、よく使うテンプレートを登録・管理したい。 (書類作成の効率をさらに上げるため)

#### 画面遷移

```
ダッシュボード → 書類生成
                    ├── テンプレート選択（一覧表示）
                    ├── 情報入力フォーム（自然言語、または項目別フォーム）
                    ├── 「プレビュー生成」ボタン
                    └── プレビュー表示エリア
                          ├── 編集機能
                          └── 「PDF出力」ボタン
```

#### データモデル（`documents`テーブル）

| 項目名 | データ型 | 制約 | 説明 |
|--------|----------|------|------|
| id | UUID | PRIMARY KEY | 書類の一意なID |
| user_id | UUID | NOT NULL, REFERENCES auth.users(id) | 書類を生成したユーザーID |
| template_id | UUID | NOT NULL, REFERENCES document_templates(id) | 使用したテンプレートID |
| title | VARCHAR(255) | NOT NULL | 書類タイトル |
| content | TEXT | NOT NULL | AIが生成した書類内容（MarkdownまたはHTML） |
| generated_at | TIMESTAMPTZ | DEFAULT NOW() | 書類生成日時 |

#### APIエンドポイント（書類関連）

| エンドポイント | Method | 機能 | リクエストボディ例 | レスポンスボディ例 |
|---------------|--------|------|--------------------|--------------------|
| `/api/document/templates` | GET | テンプレート一覧取得 | (なし) | `[{"id": "...", "name": "見積書テンプレート"}, ...]` |
| `/api/document/generate` | POST | 書類生成指示 | `{"template_id": "...", "prompt": "○○建設に見積書を"}` | `{"document_id": "...", "preview_url": "..."}` |
| `/api/document/:id/preview` | GET | 書類プレビュー取得 | (なし) | (HTMLまたは画像) |
| `/api/document/:id/pdf` | GET | PDFダウンロード | (なし) | (PDFファイル) |

#### 非機能要件（書類）

-   **生成時間**: テンプレート選択からプレビュー表示まで5秒以内。
-   **出力形式**: PDF形式での出力に対応。
-   **テンプレート**: 汎用的なビジネス書類テンプレートを複数提供。

## 4. 全体の非機能要件

-   **レスポンス**: 主要な操作（チャット応答、レポート生成、書類生成）はUXを損なわない速度で完了すること。
-   **可用性**: サービス全体の稼働率99.5%以上。
-   **セキュリティ**:
    -   ユーザー認証・認可はSupabase Authを利用し、堅牢性を確保。
    -   データはすべて暗号化（保存時、転送時）。
    -   ユーザーデータはRLSにより厳格に管理され、他のユーザーから参照できないこと。
    -   BYOK利用時、ユーザーAPIキーはセキュアに管理・利用されること。
-   **対応ブラウザ**: Chrome, Safari, Edge の最新2バージョン。
-   **モバイル対応**: iOS Safari, Android Chrome に対応し、スマートフォンからの利用を最適化。
-   **データ保持**: ユーザーの活動データ（チャット履歴、レポート、書類）は、Proプラン利用期間中および無料プランの90日間保持されること。
-   **スケーラビリティ**: Cloudflare WorkersとSupabaseにより、将来的なユーザー増加に対応できるアーキテクチャであること。
