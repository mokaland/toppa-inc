## 1. プロダクト概要

**ツミキリ**は、中小企業の経営者が「事務作業の山」から解放されるためのAIアシスタント。自然言語で指示するだけで、日常の事務作業をAIが代行するWebアプリケーション。MVPでは以下の3機能を優先して提供し、経営者の初期の「詰み」を解消することを目指す。

## 2. ターゲットユーザー

- **職業**: 建設業の社長（従業員12名）
- **課題**: 現場監督しながら見積書・請求書・日報管理。事務員は1人だが追いつかない。
- **ITリテラシー**: LINEとExcelは使える。専門ツールは苦手。

## 3. MVP機能詳細

MVPでは以下の3機能を最優先で提供する。Founding Engineerの実装計画と連携し、特にチャットアシスタントは先行して詳細化を進める。

### 3-1. 機能1: チャットアシスタント

経営者が自然言語で質問や指示を投げかけ、AIが即座に回答やアシストを行う機能。経営者の「ちょっとした相談」や「情報整理」の詰みを解消する。

#### ユーザーストーリー

1.  **認証済みユーザーとして、AIチャットに質問を投げかけたい。** (Founding Engineerにより認証機能の実装が完了しているため、この前提でチャット機能を利用できる)
2.  **AIチャットの応答が3秒以内に返ってきてほしい。** (迅速な意思決定を支援するため)
3.  **過去のチャット履歴を参照したい。** (会話のコンテキストを保持し、情報を追跡しやすくするため)
4.  **AIチャットが経営者の質問に特化した回答をしてほしい。** (一般的なAIではなく、事業課題解決に役立つ情報を得るため)
5.  **スマホからでもチャットを利用したい。** (移動中や現場でも手軽に相談できるようにするため)
6.  **重要なチャット内容は後から見返せるように保存したい。** (議事録やアイデアメモとして活用するため)

#### 画面遷移

```
ログイン → ダッシュボード
              └── チャット（トップ画面）
                    ├── 過去のチャット履歴一覧（左サイドバー）
                    └── チャット入力・表示エリア
                          ├── 入力フォーム（テキスト入力、音声入力アイコン）
                          ├── 送信ボタン
                          ├── AI応答表示
                          └── 履歴表示
```

### 3-2. 機能2: AIレポート生成

CSVまたはExcelファイルをアップロードし、自然言語で指示することでAIがデータを分析し、日本語のレポートを生成する機能。経営者の「データ集計」の詰みを解消する。

#### ユーザーストーリー

1.  **認証済みユーザーとして、CSV/Excelファイルをアップロードしたい。** (手元のデータをAIに分析させるため)
2.  **アップロードしたファイルに対して「先月の売上を部門別にまとめて」のように自然言語で指示したい。** (データ分析の専門知識がなくても、簡単にレポートを作成するため)
3.  **AIが生成したレポートをPDFやMarkdown形式でダウンロードしたい。** (他の資料に転用したり、社内共有するため)
4.  **レポート生成の進捗状況を確認したい。** (大規模なデータの場合、完了まで時間がかかる可能性があるため)
5.  **過去に生成したレポートを一覧で確認し、再ダウンロードしたい。** (必要な時にすぐ参照できるようにするため)

#### 画面遷移

```
ダッシュボード → レポート生成
                  ├── ファイルアップロードエリア
                  │     └── ファイル選択ボタン
                  ├── 自然言語指示入力フォーム
                  ├── レポート生成ボタン
                  ├── 生成進捗表示
                  └── 生成済みレポート表示エリア
                        ├── レポート内容プレビュー
                        └── ダウンロードボタン（PDF/Markdown）
```

### 3-3. 機能3: テンプレート書類生成

見積書・請求書・お礼状などのテンプレートを用意し、自然言語で必要な情報を指示することでAIが自動的に書類を生成する機能。経営者の「書類作成」の詰みを解消する。

#### ユーザーストーリー

1.  **認証済みユーザーとして、作成したい書類のテンプレートを選択したい。** (例: 見積書、請求書、お礼状など)
2.  **選択したテンプレートに対して「○○建設さんへ、屋根修理の見積書を作って。金額は35万円」のように自然言語で指示したい。** (書類作成の手間を省くため)
3.  **AIが生成した書類の内容をプレビューで確認したい。** (誤字脱字や内容の不備がないか確認するため)
4.  **確認後、PDF形式で書類をダウンロードしたい。** (印刷やメール添付で利用するため)
5.  **過去に作成した書類を一覧で確認し、再編集または再ダウンロードしたい。** (書類管理の手間を省くため)

#### 画面遷移

```
ダッシュボード → 書類生成
                  ├── テンプレート選択リスト
                  ├── 自然言語指示入力フォーム
                  ├── 書類生成ボタン
                  └── 生成済み書類プレビューエリア
                        ├── 書類内容表示
                        └── PDF出力ボタン
```

## 4. ユーザーストーリー（全体）

1. 経営者として、CSVをアップロードして「今月の売上まとめて」と言いたい。事務員に頼む手間を省くため。
2. 経営者として、「○○社に見積書を送って」と言いたい。書類作成に30分かかるのを3分にするため。
3. 経営者として、「この契約書の注意点を教えて」と相談したい。弁護士に聞くほどでもないが不安だから。
4. 経営者として、スマホからでも操作したい。現場や移動中に使うため。
5. 経営者として、自分のAPIキーを使いたい。コストを自分でコントロールするため。
6. 経営者として、過去の書類を検索したい。「先月の○○社の見積書どこだっけ？」をなくすため。
7. 経営者として、日報を音声で入力したい。キーボードが苦手だから。（Phase 2以降）
8. 経営者として、AIが作った書類をプレビューしてから確定したい。間違いがあると信用問題だから。
9. 経営者として、月額の利用料を事前に知りたい。予算オーバーが怖いから。
10. 経営者として、データが安全に管理されていると安心したい。顧客情報を扱うから。

## 5. 画面遷移（全体）

```
ログイン → ダッシュボード
              ├── チャット（機能1）
              ├── レポート生成（機能2）
              │     ├── ファイルアップロード
              │     └── レポート表示 → ダウンロード
              ├── 書類生成（機能3）
              │     ├── テンプレート選択
              │     ├── 情報入力（自然言語 or フォーム）
              │     └── プレビュー → PDF出力
              └── 設定
                    ├── APIキー設定（BYOK）
                    ├── プロフィール
                    └── プラン管理
```

## 6. データモデル設計

ツミキリの各MVP機能が利用する主要なデータエンティティと、そのデータベーステーブル設計の概要を定義する。
Founding EngineerおよびCTOの技術実装計画と進捗レポートに基づき、以下のテーブルを定義する。

### 6.1. 主要データエンティティ

| エンティティ名 | 用途 | 主要な属性（カラム） | 関連機能 |
|---|---|---|---|
| `chat_messages` | ユーザーとAIの会話履歴を保存 | `id`, `user_id`, `role`, `content`, `created_at` | チャットアシスタント |
| `reports` | AIレポート生成の履歴と結果を保存 | `id`, `user_id`, `title`, `file_name`, `file_url`, `prompt`, `result`, `created_at` | AIレポート生成 |
| `documents` | テンプレート書類生成で作成された書類を保存 | `id`, `user_id`, `document_type`, `title`, `content`, `file_url`, `created_at` | テンプレート書類生成 |
| `user_settings` | ユーザーごとの設定情報（BYOKのAPIキーなど）を保存 | `id`, `user_id`, `setting_key`, `setting_value`, `created_at` | 全機能（BYOK利用時） |

### 6.2. データ関連性

- 各テーブルは `user_id` を介して認証済みユーザーと関連付けられる。
- `user_id` はSupabaseの認証機能で管理されるユーザーIDを参照する。

## 7. 非機能要件

- レスポンス: チャット応答3秒以内
- 可用性: 99.5%以上
- セキュリティ: データ暗号化（at-rest, in-transit）、SOC2準拠を目指す
- 対応ブラウザ: Chrome, Safari, Edge（最新2バージョン）
- スマホ: iOS Safari, Android Chrome 対応
