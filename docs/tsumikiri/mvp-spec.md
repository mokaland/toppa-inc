# ツミキリ MVP仕様書

> 作成者: PdM キム・スジン
> 日付: 2026-02-15
> ステータス: 作成完了

## 1. MVPコンセプト

**ツミキリ**は、中小企業の経営者が「事務作業の山」から解放されるためのAIアシスタント。MVPでは、特に利用頻度が高く、即効性のある「レポート生成」「書類生成」「相談役」の3つの"詰み"解消にフォーカスする。

## 2. MVP機能定義

| 機能名 | 概要 | 解決する"詰み" |
|---|---|---|
| **1. AIレポート生成** | CSV/Excelをアップロードし、自然言語で指示するだけでデータ分析レポートを自動生成する。 | 売上集計や日報まとめなど、データ集計の手間。 |
| **2. テンプレート書類生成** | 見積書や請求書などのテンプレートを使い、自然言語で指示するだけで書類を即座に作成する。 | 定型的な書類作成にかかる時間と手間。 |
| **3. チャットアシスタント** | 経営に関する壁打ち相手、文章作成、アイデア出しなど、汎用的な相談に乗るAIアシスタント。 | 孤立しがちな経営者の相談相手不足。 |

## 3. ユーザーストーリー

### 基本ユーザーストーリー (10本)
1.  経営者として、CSVをアップロードして「今月の売上まとめて」と言いたい。事務員に頼む手間を省くため。
2.  経営者として、「○○社に見積書を送って」と言いたい。書類作成に30分かかるのを3分にするため。
3.  経営者として、「この契約書の注意点を教えて」と相談したい。弁護士に聞くほどでもないが不安だから。
4.  経営者として、スマホからでも操作したい。現場や移動中に使うため。
5.  経営者として、自分のAPIキーを使いたい。コストを自分でコントロールするため。
6.  経営者として、過去の書類を検索したい。「先月の○○社の見積書どこだっけ？」をなくすため。
7.  経営者として、日報を音声で入力したい。キーボードが苦手だから。
8.  経営者として、AIが作った書類をプレビューしてから確定したい。間違いがあると信用問題だから。
9.  経営者として、月額の利用料を事前に知りたい。予算オーバーが怖いから。
10. 経営者として、データが安全に管理されていると安心したい。顧客情報を扱うから。

### MVP機能特化ユーザーストーリー (5本追加)
11. **[レポート]** 複数の店舗を経営するオーナーとして、各店舗の売上CSVをまとめてアップロードし、「店舗Aと店舗Bの売上を比較して、どちらが客単価が高いか分析して」と指示したい。事業判断のスピードを上げるため。
12. **[書類生成]** 毎月請求書を発行するウェブデザイナーとして、「取引先リストにある全社宛に、今月分の請求書をまとめて下書き作成して」と指示したい。月末の繰り返し作業を自動化するため。
13. **[チャット]** 新規事業を検討中の経営者として、「飲食店の開業を考えている。必要な許認可と、概算の初期費用について教えて」と相談したい。専門家を探す前に、手軽に一次情報が欲しいから。
14. **[機能連携]** 営業部長として、「今月の売上レポートで目標達成率が最も高かった営業担当者トップ3をリストアップし、彼らへの感謝を伝えるお礼状の文面を作って」と指示したい。データに基づいた迅速なチームマネジメントのため。
15. **[非機能]** 経営者として、事務スタッフ用にアカウントを追加し、書類作成は任せたいが、全社の売上データが含まれるレポート機能へのアクセスは制限したい。セキュアな権限管理のため。(※権限管理はMVP後の検討課題)

## 4. 画面遷移図 (MVP範囲)

```
ログイン
 │
 └─ ダッシュボード
      │
      ├─ 1. チャットアシスタント (メイン画面)
      │
      ├─ 2. レポート生成
      │    ├─ ファイルアップロード画面
      │    └─ レポート表示・ダウンロード画面
      │
      ├─ 3. 書類生成
      │    ├─ テンプレート選択画面
      │    └─ プレビュー・PDF出力画面
      │
      └─ 設定
           └─ APIキー設定 (BYOK)
```

## 5. データモデル

CTO（マルコ・ロッシ）とFounding Engineer（カルロス・メンデス）が策定した `implementation-plan.md` のデータベーススキーマを正とする。PdMとして、以下のデータが永続化されることを要求する。

| データ | 格納テーブル (想定) | 目的 |
|---|---|---|
| ユーザーの会話履歴 | `chat_messages` | コンテキスト維持、過去の相談の参照 |
| アップロードしたファイル | Supabase Storage | レポート再生成、過去データの参照 |
| 生成されたレポート | `reports` | 過去の分析結果の蓄積・確認 |
| 生成された書類 | `documents` | 発行済み書類の管理・再発行 |
| ユーザー設定 | `user_settings` | BYOKのAPIキー保持など |
