> 日付: 2026-02-16

## 1. プロダクト概要

ツミキリは、中小企業の経営者が「事務作業の山」から解放されるためのAIアシスタント。自然言語で指示するだけで、日常の事務作業をAIが代行する。

## 2. MVP機能定義

Q1四半期計画に基づき、以下の3つのMVP機能を定義する。

### 2.1. AIレポート生成

- **機能概要**: CSVまたはExcelファイルをアップロードし、自然言語で指示することでAIがデータを分析し、レポートを生成する。
- **ユーザーストーリー**:
    - 経営者として、CSVをアップロードして「今月の売上まとめて」と言いたい。事務員に頼む手間を省くため。
    - 経営者として、月ごとの売上推移をグラフで表示してほしい。事業の状況を視覚的に把握するため。
    - 経営者として、部門別の利益率を分析してほしい。どの部門に注力すべきか判断するため。
    - 経営者として、生成されたレポートをPDFでダウンロードしたい。社内共有や報告に使うため。
    - 経営者として、過去に生成したレポートを一覧で確認したい。後から参照できるようにするため。
    - 経営者として、レポート生成時に使用するデータ範囲（例: 特定の期間、特定の顧客）を指定したい。必要な情報だけを抽出するため。
    - 経営者として、AIが生成したレポートの内容について、「この部分をもっと詳しく説明して」と追加で質問したい。レポート内容を深く理解し、疑問点を解消するため。
    - 経営者として、定期的に（例: 毎月1日）特定のCSVファイルから自動でレポートを生成し、メールで受け取りたい。定型業務を自動化し、報告漏れを防ぐため。
    - 経営者として、生成されたレポートを、グラフの種類（棒グラフ、円グラフ、折れ線グラフなど）や表示項目を自由にカスタマイズして出力したい。見せたい情報に合わせて柔軟に調整するため。
    - 経営者として、Excelファイルをアップロードして、「このシートのデータを使って、商品Aと商品Bの売上を比較して」と指示したい。異なるフォーマットのデータも扱えるようにするため。
    - 経営者として、アップロードしたExcelファイルに複数のシートがある場合、どのシートを分析対象にするか指定したい。不要なシートのデータを含めないようにするため。
- **画面遷移**:
    1.  `ダッシュボード`:
        - レポート生成機能への導線ボタン
        - 過去のレポート履歴へのリンク
    2.  `レポート生成トップ`:
        - 「ファイルをアップロードしてレポートを生成」ボタン
        - 「過去のレポートを見る」ボタン
    3.  `ファイルアップロード画面`:
        - ドラッグ＆ドロップまたはファイル選択によるCSV/Excelファイルアップロードエリア
        - アップロード可能なファイル形式とサイズ上限の表示（例: CSV, XLSX, 最大10MB）
        - アップロードされたファイルのプレビュー（ファイル名、シート名、最初の数行のデータ）
        - 「次へ」ボタン
    4.  `分析指示入力画面`:
        - 自然言語での分析指示入力テキストエリア
        - 入力例の提示（例: 「先月の売上を部門別にまとめてください」）
        - 「レポート生成」ボタン
    5.  `レポート表示画面`:
        - 生成されたレポートの表示（Markdown形式）
        - レポート内容に対する追加質問入力エリア
        - 「PDFダウンロード」ボタン
        - 「Markdownダウンロード」ボタン
        - 「レポートを保存」ボタン
    6.  `レポート履歴画面`:
        - 過去に生成されたレポートの一覧表示（タイトル、生成日時）
        - 各レポートへのリンク
        - 検索・フィルタリング機能
- **データモデル**:
    ```sql
    -- レポート履歴テーブル
    CREATE TABLE reports (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
        title VARCHAR(255) NOT NULL,
        file_name VARCHAR(255),
        file_url TEXT,
        prompt TEXT NOT NULL,
        result TEXT,
        created_at TIMESTAMPTZ DEFAULT NOW()
    );
    ```
- **APIエンドポイント**:
    - `POST /api/report/upload`: ファイルアップロード
    - `POST /api/report/generate`: AIによるレポート生成
    - `GET /api/reports`: レポート履歴一覧取得
    - `GET /api/reports/:id`: 特定レポート詳細取得
- **非機能要件**:
    - ファイルアップロードサイズ上限: 10MB
    - レポート生成応答時間: 30秒以内

### 2.2. テンプレート書類生成

- **機能概要**: 見積書・請求書・お礼状などのテンプレートから、自然言語またはフォーム入力で情報を流し込み、書類を生成する。
- **ユーザーストーリー**:
    - 経営者として、「○○建設さんへ、屋根修理の見積書を作って。金額は35万円」と言いたい。書類作成に30分かかるのを3分にするため。
    - 経営者として、生成された書類をPDFで出力したい。印刷して郵送するため。
    - 経営者として、生成された書類をメールに添付して送信したい。顧客への迅速な対応のため。
    - 経営者として、よく使う書類のテンプレートをカスタマイズしたい。自社のフォーマットに合わせるため。
    - 経営者として、過去に生成した書類を検索・参照したい。「先月の○○社の見積書どこだっけ？」をなくすため。
    - 経営者として、AIが作成した書類をプレビューしてから確定したい。間違いがあると信用問題だから。
    - 経営者として、書類生成時に必要な情報（宛名、金額、日付など）をフォーム形式で入力したい。自然言語入力が苦手な場合でも正確に入力するため。
    - 経営者として、生成された書類の特定の項目（例: 担当者名、商品名）を後から手動で修正したい。AIが生成した内容を微調整するため。
    - 経営者として、複数のテンプレートをカテゴリ別に整理して表示してほしい。目的のテンプレートを素早く見つけるため。
    - 経営者として、契約書のような複雑な書類を生成する際に、AIに「この条項は含めるべきか？」と相談したい。法的なリスクを低減するため。
- **画面遷移**:
    1.  `ダッシュボード`:
        - 書類生成機能への導線ボタン
        - 過去の書類履歴へのリンク
    2.  `テンプレート選択画面`:
        - カテゴリ別（見積書、請求書、お礼状など）のテンプレート一覧表示
        - テンプレートプレビュー
        - 「このテンプレートで作成」ボタン
    3.  `情報入力画面`:
        - 自然言語入力エリア（例: 「○○社に見積書、金額は10万円で」）
        - または、テンプレートに応じたフォーム入力エリア（宛名、商品名、金額など）
        - 「プレビュー生成」ボタン
    4.  `プレビュー・編集画面`:
        - AIが生成した書類のプレビュー表示
        - 必要に応じてテキスト編集が可能なエリア
        - 「PDF出力」ボタン
        - 「メール送信」ボタン（Phase 2）
        - 「保存」ボタン
    5.  `書類履歴画面`:
        - 過去に生成された書類の一覧表示（タイトル、生成日時）
        - 各書類へのリンク
        - 検索・フィルタリング機能
- **データモデル**:
    ```sql
    -- 書類履歴テーブル
    CREATE TABLE documents (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
        template_id UUID NOT NULL, -- 使用したテンプレートID
        title VARCHAR(255) NOT NULL,
        content TEXT NOT NULL, -- 生成された書類の最終内容（Markdown/HTMLなど）
        generated_at TIMESTAMPTZ DEFAULT NOW()
    );

    -- テンプレートテーブル
    CREATE TABLE templates (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        name VARCHAR(255) NOT NULL,
        category VARCHAR(100),
        content TEXT NOT NULL, -- テンプレートの内容
        created_at TIMESTAMPTZ DEFAULT NOW(),
        updated_at TIMESTAMPTZ DEFAULT NOW()
    );
    ```
- **APIエンドポイント**:
    - `POST /api/document/generate`: AIによる書類生成
    - `GET /api/templates`: テンプレート一覧取得
    - `GET /api/documents`: 書類履歴一覧取得
    - `GET /api/documents/:id`: 特定書類詳細取得
- **非機能要件**:
    - 書類生成応答時間: 10秒以内

### 2.3. チャットアシスタント

- **機能概要**: 経営者向けのAIチャット。事業に関する質問、アドバイス、文章作成などに対応。過去の会話履歴を保持。
- **ユーザーストーリー**:
    - 経営者として、「この契約書の注意点を教えて」と相談したい。弁護士に聞くほどでもないが不安だから。
    - 経営者として、過去の会話履歴を保持してほしい。同じ質問を繰り返さなくて済むようにするため。
    - 経営者として、スマホからでもチャットしたい。現場や移動中に使うため。
    - 経営者として、「今月の売上目標達成のために何をすべきか」と相談したい。事業戦略のヒントを得るため。
    - 経営者として、チャットで作成した文章（例: 顧客へのお詫びメール）をコピーして使いたい。文章作成の手間を省くため。
    - 経営者として、AIアシスタントに自分の事業内容や業界の情報を学習させたい。よりパーソナライズされたアドバイスを得るため。
    - 経営者として、チャットの会話中にファイルを添付してAIに分析してもらいたい。文脈を理解した上でアドバイスをもらうため。
    - 経営者として、AIアシスタントの応答速度が速いと嬉しい。思考を止めずに会話を進めたいから。
    - 経営者として、チャットの会話履歴を削除したい。プライベートな内容を消去するため。
    - 経営者として、複数のチャットセッションを使い分けたい。異なるテーマで会話を整理するため。
    - 経営者として、AIが回答に詰まった時に、別のAIモデル（例: GPT-4o, Claude Opus）に切り替えて質問したい。より適切な回答を得るため。
- **画面遷移**:
    1.  `ダッシュボード`:
        - チャットアシスタントへの導線ボタン
    2.  `チャット画面`:
        - 会話履歴表示エリア
        - メッセージ入力テキストエリア
        - 「送信」ボタン
        - 会話履歴クリアボタン
        - 新規チャット開始ボタン
        - 過去のチャットセッション一覧（サイドバーなど）
- **データモデル**:
    ```sql
    -- 会話履歴テーブル
    CREATE TABLE chat_messages (
        id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
        user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
        role VARCHAR(10) NOT NULL CHECK (role IN ('user', 'assistant', 'system')),
        content TEXT NOT NULL,
        created_at TIMESTAMPTZ DEFAULT NOW()
    );
    ```
- **APIエンドポイント**:
    - `POST /api/chat`: チャット送信・AI応答取得
    - `GET /api/chat/history`: 会話履歴取得
    - `GET /api/chat/history/:sessionId`: 特定セッションの履歴取得
- **非機能要件**:
    - チャット応答速度: 3秒以内

## 3. 共通非機能要件

- **認証・認可**:
    - 全ての機能利用においてユーザー認証を必須とする。
    - Supabase Authを利用し、ユーザーごとにデータアクセスを制御する（ROW LEVEL SECURITY）。
    - 各ユーザーは自身のデータのみにアクセス可能とする。
- **セキュリティ**:
    - データ暗号化（at-rest, in-transit）
    - SOC2準拠を目指す
- **可用性**: 99.5%以上
- **対応ブラウザ**: Chrome, Safari, Edge（最新2バージョン）
- **スマホ対応**: iOS Safari, Android Chrome 対応
