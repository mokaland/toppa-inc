## 1. 概要

本仕様書は、プロダクト「ツミキリ」のMVP（Minimum Viable Product）開発に必要な要件を定義する。
プロダクト企画書 `docs/product-proposal.md` を正とし、本仕様書はそれを技術的に詳細化するものである。

## 3. 機能詳細

### MVP-1: AIレポート生成

#### 3.1.1 ユーザーストーリー
- 経営者として、CSVをアップロードして「今月の売上まとめて」と言いたい。事務員に頼む手間を省くため。

#### 3.1.2 UIコンポーネント
- ファイルアップロードエリア（ドラッグ＆ドロップ対応）
- 指示入力用のテキストエリア
- 「生成」ボタン
- レポート表示エリア（Markdown形式）
- 「ダウンロード」ボタン（Markdown/PDF）
- ローディングスピナー

#### 3.1.3 動作要件
1.  ユーザーはCSVまたはExcel（.xlsx）ファイルをアップロードする。
2.  ファイルアップロード後、プレビューとして先頭5行が表示される。
3.  ユーザーは「先月の売上を部門別にグラフ化して」のような自然言語で指示を入力する。
4.  「生成」ボタンを押すと、バックエンドにファイルと指示が送信される。
5.  バックエンドはAI（LLM）を用いてデータを分析・集計し、結果をMarkdown形式のレポートとして生成する。
6.  生成されたレポートがフロントエンドの表示エリアに表示される。
7.  ユーザーはレポートをMarkdown形式またはPDF形式でダウンロードできる。

#### 3.1.4 エラーハンドリング
- 対応していないファイル形式がアップロードされた場合、「対応しているファイル形式はCSVとXLSXです」と表示する。
- ファイルサイズが5MBを超える場合、「ファイルサイズは5MB以下にしてください」と表示する。
- AIの処理でエラーが発生した場合、「レポートの生成に失敗しました。もう一度お試しください」と表示する。

### MVP-2: テンプレート書類生成

#### 3.2.1 ユーザーストーリー
- 経営者として、「○○社に見積書を送って」と言いたい。書類作成に30分かかるのを3分にするため。

#### 3.2.2 UIコンポーネント
- テンプレート選択ドロップダウン（「見積書」「請求書」）
- 指示入力用のテキストエリア
- 「生成」ボタン
- 書類プレビューエリア
- 「PDFダウンロード」ボタン

#### 3.2.3 動作要件
1.  ユーザーはテンプレート（「見積書」または「請求書」）を選択する。
2.  ユーザーは「宛名：株式会社〇〇、件名：ウェブサイト制作、金額：500,000円、納期：2026年3月31日」のように、自然言語で必要事項を入力する。
3.  「生成」ボタンを押すと、バックエンドにテンプレート種別と指示が送信される。
4.  バックエンドはAI（LLM）を用いて指示から必要情報（宛名、金額、件名など）を抽出し、対応するテンプレートに埋め込む。
5.  生成された書類がプレビューとして表示される。
6.  ユーザーは「PDFダウンロード」ボタンで書類をダウンロードできる。

#### 3.2.4 エラーハンドリング
- 指示から必要情報が抽出できなかった場合、「情報の抽出に失敗しました。項目を明記して再度お試しください。（例：宛名：株式会社〇〇）」と表示する。

### MVP-3: チャットアシスタント

#### 3.3.1 ユーザーストーリー
- 経営者として、「この契約書の注意点を教えて」と相談したい。弁護士に聞くほどでもないが不安だから。

#### 3.3.2 UIコンポーネント
- チャットウィンドウ
- メッセージ入力エリア
- 「送信」ボタン

#### 3.3.3 動作要件
1.  ユーザーは経営に関する相談や質問を自由に入力し、送信する。
2.  バックエンドは、経営者支援に特化したシステムプロンプトを用いてAI（LLM）から回答を生成する。
3.  AIの回答がチャットウィンドウに表示される。
4.  会話の履歴は保持され、過去の文脈を踏まえた回答が行われる。

#### 3.3.4 システムプロンプトの方向性
- あなたは中小企業の経営者を20年間支援してきたベテラン経営コンサルタントです。
- 常に経営者の視点に立ち、具体的で、すぐに実行可能なアドバイスを提供してください。
- 専門用語は避け、平易な言葉で説明してください。

## 4. データモデル (Supabase)

- ER図や詳細なスキーマはCTOが別途 `docs/tsumikiri/tech-architecture.md` にて定義する。ここではPdMからの要求仕様を記載する。

**`users`**
| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid | ユーザーID (Supabase Auth連携) |
| email | text | メールアドレス |
| created_at | timestampz | 作成日時 |

**`documents`**
| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid | ドキュメントID |
| user_id | uuid | ユーザーID (FK to users.id) |
| type | text | `report` or `invoice` or `quote` |
| title | text | ドキュメントのタイトル |
| source_file_url | text | (レポート用) 元データのURL |
| content | text | 生成された内容 (Markdown) |
| created_at | timestampz | 作成日時 |

**`chat_histories`**
| カラム名 | 型 | 説明 |
|---|---|---|
| id | uuid | チャット履歴ID |
| user_id | uuid | ユーザーID (FK to users.id) |
| messages | jsonb | `[{ "role": "user", "content": "..." }, ...]` |
| created_at | timestampz | 作成日時 |
| updated_at | timestampz | 更新日時 |

## 5. APIエンドポイント (案)

- 詳細なAPI設計はCTOが別途 `docs/tsumikiri/tech-architecture.md` にて定義する。

- `POST /api/reports`
  - **説明**: レポートを生成する
  - **リクエスト**: `multipart/form-data` (file, prompt)
  - **レスポンス**: `{ "content": "..." }` (Markdown)

- `POST /api/documents`
  - **説明**: テンプレートから書類を生成する
  - **リクエスト**: `{ "template_type": "quote", "prompt": "..." }`
  - **レスポンス**: `{ "content": "..." }` (HTML/Markdown for preview)

- `POST /api/chat`
  - **説明**: チャットに応答する
  - **リクエスト**: `{ "messages": [...] }`
  - **レスポンス**: `{ "reply": "..." }`
