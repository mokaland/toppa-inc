# 技術アーキテクチャ設計書レビュー

- 日付: 2026-02-17
- ステータス: フィードバック

## 1. 総評

全体的な技術選定とアーキテクチャは合理的であり、プロダクトの方向性と一致している。特にCloudflareを中心とした構成は、MVPの迅速な立ち上げと将来のスケール性に貢献すると高く評価する。

ただし、MVP仕様書で定義された要件と技術的実現性の間に、以下の2点の重大なリスクが確認された。Founding Engineerが実装に着手する前に、これらの点について具体的な解決策を提示されたい。

## 2. [要対応] リスクと確認事項

### 懸念事項1: Excel (.xlsx) ファイルの処理

- **指摘:**
  `mvp-spec.md` (MVP-1) では、ユーザーが「.xlsx」形式のファイルをアップロードできることが要件となっている。しかし、`tech-architecture.md`で選択されているバックエンド環境 **Cloudflare Workers** のEdge Runtimeでは、Node.jsの標準ライブラリや、xlsxファイルをパースするための大規模なサードパーティライブラリが動作しないという強い制約がある。この点に関する具体的な実装方針が設計書に記載されていない。

- **依頼:**
  この技術的制約を乗り越えるための具体的な解決策を、以下の選択肢などを参考に検討し、アーキテクチャ設計書に追記すること。
  - **案A:** クライアントサイド（ブラウザ）でxlsxをパースし、CSV形式に変換してからサーバーに送信する。
  - **案B:** MVPフェーズでは対応フォーマットを「CSVのみ」に限定し、xlsx対応は将来的な課題とする。
  - **案C:** xlsxのパース処理のみを行う、Node.js互換の別サーバーレス関数（例: Google Cloud Functions Gen2）をAPIとして呼び出す。

### 懸念事項2: PDFファイルのサーバーサイド生成

- **指摘:**
  `mvp-spec.md` (MVP-1, MVP-2) では、生成されたレポートや書類をPDF形式でダウンロードできることが要件となっている。これもxlsxと同様に、Cloudflare Workers上でサーバーサイドでPDFを生成するライブラリには強い制約が存在する。

- **依頼:**
  サーバーサイドでのPDF生成について、技術的な実現可能性を調査し、具体的な実装方針（利用ライブラリやサービスなど）をアーキテクチャ設計書に追記すること。実現が困難な場合は、代替案（例: フロントエンドでの生成、Markdown形式でのダウンロードのみに限定）を速やかに提案すること。
