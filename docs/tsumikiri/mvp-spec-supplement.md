# ツミキリ MVPプロダクト仕様書 補足説明ドキュメント

> 作成: PdM キム・スジン
> 日付: 2026-02-16
> ステータス: ドラフト

本ドキュメントは、`docs/tsumikiri/mvp-spec.md` で定義されたMVP機能の詳細な補足説明を提供します。Founding Engineerのカルロス・メンデスが実装を進める上で、UI/UX、具体的なインタラクション、AIの応答仕様、エラーハンドリングなど、より具体的な情報を提供することを目的とします。

## 1. チャットアシスタント機能（機能3）

### 1-1. UI/UXとインタラクション

#### メッセージ入力と送信
- **入力フィールド**: ユーザーは画面下部のテキストエリアにメッセージを入力します。テキストエリアは複数行入力に対応し、入力内容に応じて自動で高さが拡張されます（最大5行程度）。
- **送信ボタン**: テキストエリアの右隣に送信ボタン（紙飛行機アイコンなど）を配置します。エンターキーでの送信も可能とします。
- **入力中の表示**: ユーザーがメッセージを入力している間は、送信ボタンがアクティブ状態（色変更など）になります。

#### メッセージ表示
- **吹き出しデザイン**:
    - ユーザーメッセージ: 右側に配置し、背景色を青系（例: #E0F2F7）にします。
    - AIアシスタントメッセージ: 左側に配置し、背景色をグレー系（例: #F0F0F0）にします。
- **アバター**: AIアシスタントメッセージの左側には、ツミキリのロゴまたはシンプルなAIアイコンを配置します。ユーザーメッセージにはアバターは不要です。
- **表示内容**: メッセージ本文のみを表示します。送信時刻は不要です。
- **スクロール**: メッセージが増えるにつれて、チャット履歴は自動で最下部にスクロールします。ユーザーが手動でスクロールしている間は自動スクロールを一時停止し、新しいメッセージが来たら「新着メッセージ」のような表示を出し、クリックで最下部に移動できるようにします。

#### AI応答のトーン＆マナー
- **ペルソナ**: 経営者の良き相談相手として、専門的かつ実践的なアドバイスを提供します。共感を示しつつも、具体的な行動を促すような言葉遣いを心がけます。
- **具体性**: 抽象的な回答は避け、可能な限り具体的な数字、手順、事例を交えて説明します。
- **簡潔さ**: 一度に長文を返すのではなく、要点をまとめて簡潔に回答します。必要に応じて箇条書きやステップ形式で分かりやすく提示します。
- **敬語**: 丁寧語を使用します。

#### エラーメッセージの表示
- **ネットワークエラー**:
    - 「ネットワークに接続できません。インターネット接続を確認してください。」
    - チャット入力フィールドの下、またはモーダルで表示します。
- **AI応答エラー**:
    - 「AIの応答に失敗しました。時間をおいて再度お試しください。問題が続く場合は、サポートにお問い合わせください。」
    - AIアシスタントの吹き出しとして表示します。
- **入力バリデーションエラー**:
    - 「メッセージが空です。何か入力してください。」
    - 入力フィールドの下に赤文字で表示します。

#### 過去の会話履歴と新規セッション
- **履歴表示**: ログイン後、ユーザーは過去の会話履歴を時系列で閲覧できます。初期表示は最新の会話セッションとします。
- **セッション管理**: 現時点では明示的なセッション切り替え機能はMVP範囲外とします。ユーザーがチャット画面を離れても、戻ってきた際には前回の会話履歴が継続して表示されるようにします。
- **新規会話の開始**: ユーザーが明確に「新しい会話を始めたい」と意図する機能（例: 「新しいチャット」ボタン）はPhase 2で検討します。MVPでは、既存の会話を継続する形式を基本とします。

### 1-2. プロンプト設計に関する補足

- **システムプロンプトの意図**:
    - 「あなたは中小企業の経営者を支援するAIアシスタント『ツミキリ』です。彼らの抱える事務作業の『詰み』を解消し、経営に集中できるよう、具体的かつ実践的なアドバイスを提供してください。」
    - この意図をAIモデルに正確に伝えるためのシステムプロンプトを設計してください。
- **ユーザー入力の処理**:
    - ユーザーからの入力はそのままAIモデルに渡すことを基本とします。
    - ただし、不適切な内容（公序良俗に反する、個人情報など）が含まれる場合は、AIモデルに渡す前にフィルタリングする機構をPhase 2で検討します。MVPでは、AIプロバイダーのフィルタリング機能に依存します。

### 1-3. 非機能要件補足

- **レスポンシブデザイン**:
    - スマートフォン（幅375px程度）での表示を優先してデザインします。PC表示では、チャットエリアの最大幅を設定し、左右に余白を持たせることで視認性を確保します。
    - 入力フィールド、送信ボタン、メッセージ吹き出しは、画面幅に応じて適切にリサイズされます。
- **チャット応答速度**: AIからの応答は、ユーザーがメッセージを送信してから3秒以内に最初の文字が表示され始めることを目標とします。
