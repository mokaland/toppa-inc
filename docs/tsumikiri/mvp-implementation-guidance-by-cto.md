# ツミキリ MVP実装ガイドライン（CTO視点）

> 作成: CTO マルコ・ロッシ
> 日付: 2026-02-17
> ステータス: ドラフト

## 1. はじめに

本ガイドラインは、Founding EngineerがツミキリMVPの実装に着手するにあたり、`docs/tsumikiri/mvp-spec.md` (プロダクト仕様書) および `docs/tech-direction.md` (技術方針書) を補完し、具体的な実装方針と考慮事項を提供するものです。特に「AIレポート生成」機能に焦点を当て、初期開発をスムーズに進めるための指針とします。

## 2. 初期開発環境セットアップのポイント

### 2.1. Cloudflare Workers + Hono プロジェクトの初期化
- `wrangler generate <project-name> hono` コマンドでHonoテンプレートをベースにプロジェクトを開始する。
- TypeScript strict mode を有効にし、`tsconfig.json`で厳密な型チェックを設定する。

### 2.2. Supabase クライアントのセットアップ
- `supabase-js` クライアントライブラリをインストールし、Workers環境で利用できるように設定する。
- SupabaseのURLとAnon KeyはCloudflare Workersのシークレットとして管理する（`wrangler secret put SUPABASE_URL`, `wrangler secret put SUPABASE_ANON_KEY`）。

## 3. AIレポート生成機能の実装方針

### 3.1. ファイルアップロード処理

- **エンドポイント設計**: `POST /api/reports/upload` のようなエンドポイントをHonoで定義する。
- **ファイルハンドリング**: Cloudflare WorkersではNode.jsの`fs`モジュールが利用できないため、`Request.arrayBuffer()`や`Request.formData()`を使用してファイルを処理する。
    - CSV/ExcelファイルのMIMEタイプを検証し、不正なファイルを拒否する。
- **Supabase Storageへの保存**:
    - アップロードされたファイルを一時的にSupabase Storageに保存する。バケットポリシーとRLSを設定し、ユーザーごとにアクセスを制限する。
    - ファイル名にはユーザーIDとタイムスタンプを含め、一意性を確保する。

### 3.2. 自然言語指示のパースとAIプロンプト生成

- **プロンプトエンジニアリング**: ユーザーの自然言語指示とアップロードされたデータの内容を組み合わせ、AIモデル（BYOKまたはマネージド）に最適なプロンプトを動的に生成する。
    - レポートの目的、形式（PDF/Markdown）、分析項目などを明確にAIに伝える。
    - ユーザーがアップロードしたデータのスキーマ情報（CSVヘッダーなど）をプロンプトに含めることで、AIの分析精度を向上させる。
- **AIモデルの選択**: ユーザーがBYOKで選択したAIモデル（OpenAI, Anthropic, Google）に応じて、適切なAPIクライアントを使用する。

### 3.3. AI応答の処理とレポート生成ロジック

- **AIからの応答処理**: AIモデルからの応答は通常テキスト形式で返される。これをMarkdown形式として解釈し、必要に応じて構造化する。
- **レポート形式の変換**:
    - **Markdown出力**: AIからのMarkdown応答をそのままユーザーに提供する。
    - **PDF出力**: Cloudflare Workers環境で直接PDFを生成するのは困難な場合がある（重いライブラリが利用できないため）。
        - 検討1: AIが生成したMarkdownをフロントエンドでPDFに変換する（jsPDFなどのライブラリ）。
        - 検討2: 外部のPDF生成APIサービスを利用する（コストとパフォーマンスを考慮）。
        - 検討3: シンプルなレポートであれば、AIがHTMLを生成し、それをPDF変換するサービスに渡す。
    - **Excel出力**: 現状のMVPではスコープ外とするが、将来的な拡張として検討。Workersの制約（xlsxライブラリ不可）を考慮し、CSV形式でのデータ提供に留めるか、外部サービスを検討する。

### 3.4. 処理状況のリアルタイム表示

- **ポーリング**: 短期的には、フロントエンドから定期的にAPIを呼び出し、レポート生成のステータスをポーリングする方法が最もシンプル。
- **WebSocket (将来的な検討)**: よりリアルタイムなUXを提供するために、Cloudflare WorkersのWebSocket機能やDurable Objectsを将来的に検討する。

## 4. テスト方針

- **ユニットテスト**: HonoのAPIエンドポイント、ファイルハンドリング、プロンプト生成ロジックなど、各コンポーネントのユニットテストをVitestで実装する（カバレッジ80%目標）。
- **E2Eテスト**: Playwrightを用いて、ファイルアップロードからレポート生成、ダウンロードまでの一連の主要フローのE2Eテストを実装する。
- **AI応答テスト**: モックAPIや固定の入力データを用いて、AIのプロンプトが期待通りに動作し、適切な応答を生成するかを検証する。

## 5. セキュリティに関する考慮事項

- **BYOK方式のAPIキー管理**: ユーザーから提供されたAPIキーは、Cloudflare Workersのシークレットとして一時的に利用し、ログには記録せず、リクエスト完了後にメモリから破棄する。
- **Supabase RLS**: Supabase StorageおよびDatabaseにおいて、ユーザーが自身のデータのみにアクセスできるよう、Row Level Security (RLS) を厳密に設定する。
- **入力データのサニタイズ**: ユーザーがアップロードするファイルや自然言語指示に含まれる悪意のある入力（例: インジェクション攻撃）に対して、適切なサニタイズ処理を実装する。

## 6. 今後の課題・検討事項

- 大規模なファイルアップロードに対するパフォーマンス最適化。
- AIモデルの応答速度向上とコスト最適化。
- PDF生成の最適なソリューションの選定。
- 複数ユーザーの同時リクエストに対するスケーラビリティ。
